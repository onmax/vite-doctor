The MCP Rule Pack checks the tools an MCP server defines. A server can work in your own tests and still be rejected later: Anthropic's Connectors Directory flags tools without a title or a safety hint, and clients treat a tool that declares neither `readOnlyHint` nor `destructiveHint` as destructive. A tool can also answer with more tokens than its data needs, such as indented JSON. The pack finds those problems in source, before you submit.

It activates on its own when Project Inventory contains `h3-mcp`, `okmcp`, `nitro-mcp-toolkit`, `@nuxtjs/mcp-toolkit`, `vite-hub`, `@vite-hub/mcp`, `@modelcontextprotocol/sdk`, or `@modelcontextprotocol/server`.

## Install and run

Install Vite Doctor in the project:

```bash
pnpm add -D vite-doctor
```

The Recommended Preset runs automatically:

```bash
pnpm vite-doctor .
```

To diagnose one Rule, select it with `--rules`:

```bash
pnpm vite-doctor . --rules mcp/tools/require-annotation-title
```

## What Doctor reads

Doctor builds an inventory of tool definitions from these calls:

| Library                                                     | Definition                                                                                                      |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `h3-mcp`, `okmcp`                                           | `defineTool()` imported from the package                                                                        |
| `nitro-mcp-toolkit`                                         | `defineMcpTool()` imported from the package                                                                     |
| `@nuxtjs/mcp-toolkit`                                       | `defineMcpTool()`, imported or auto-imported                                                                    |
| `vite-hub`, `@vite-hub/mcp`                                 | `defineMcpTool()` imported from `vite-hub/mcp` or `@vite-hub/mcp`                                               |
| `@modelcontextprotocol/sdk`, `@modelcontextprotocol/server` | `server.registerTool(name, config, handler)` on a `const` initialized with `new McpServer()` from an SDK import |

A local function that happens to share one of these names is skipped.

Both toolkits name a tool discovered under `server/mcp/tools/` after its file, and fill its top-level `title` from the file name. Doctor applies the same naming to default exports in that directory. Neither toolkit copies that title into `annotations`, which is why the inventory reads the two separately. ViteHub names a tool after its path below `mcp/tools/`, without the extension or a trailing `/index`. It ignores the definition's `name` and fills no title.

Annotations can be an object literal or spread shared objects into one. Doctor follows a spread to a `const` in the same file, to an export of a relatively imported file, and to a unique export in an auto-imported `server/utils` or `shared/utils` file. When it can't follow a spread or read a key, it reports nothing for that tool rather than guess.

An annotation title must be a non-empty string. A safety hint must set `readOnlyHint` or `destructiveHint` to `true`; `false`, `undefined`, and values of the wrong type don't satisfy the Connector criteria. The MCP0002 fix follows the hints a tool declares: with `readOnlyHint: false` it asks for `destructiveHint: true`, and with both hints `false`, which MCP uses for tools that only add data, it explains that the Directory review will still flag the tool. Doctor follows statically readable constant values and respects the order of spread overrides. When a relevant value is only known at runtime, it skips that Rule for the tool.

Doctor looks for indented JSON returned directly by the handler or in a `{ type: 'text', text: … }` block in its returned `content` array. It follows returned helper calls up to two levels deep, including a shared `toStructuredResult()` in `server/utils`. Metadata, structured content, unrelated callbacks, and indents Doctor can't read are skipped. To compact the JSON without changing which data is serialized, remove only the third argument to `JSON.stringify()` and keep the replacer.

Doctor reads source only. A tool that a Nitro hook or plugin changes at runtime is diagnosed as written.

## Check a running server

Doctor never connects to a server. To check the tools a running server sends, and what each MCP client does with them, use [loadsheet](https://loadsheet.dev):

```bash
npx loadsheet mcp http://localhost:3000/mcp
```

For a server that needs a token, add `--header "Authorization: Bearer $TOKEN"`. Its codes, including the client-limit checks that were MCP0005 to MCP0010 in earlier Doctor releases, are documented at [loadsheet.dev/docs/reference/mcp](https://loadsheet.dev/docs/reference/mcp).
