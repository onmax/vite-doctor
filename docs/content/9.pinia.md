The Pinia Rule Pack checks `defineStore()` calls in Vue, Vite, and Nuxt projects. Pinia is a Vue ecosystem library rather than part of Vue or Nuxt, so the pack activates on its own when Project Inventory contains `pinia` or `@pinia/nuxt`.

## Install and run

Install Vite Doctor in the project:

```bash
pnpm add -D vite-doctor
```

The Recommended Preset runs automatically and reports store ids that more than one `defineStore()` call registers:

```bash
pnpm vite-doctor .
```

The Strict Preset adds the `use<Id>Store` naming convention:

```bash
pnpm vite-doctor . --extends auto,pinia/strict
```

To diagnose one Rule, select it with `--rules`. Strict-only Rules also need the Strict Preset:

```bash
pnpm vite-doctor . --rules pinia/stores/unique-store-id
pnpm vite-doctor . --extends auto,pinia/strict --rules pinia/stores/store-name-matches-id
```

## What Doctor reads

Doctor recognizes `defineStore` imported from `pinia`, including aliased and namespace imports. It also recognizes `defineStore` with no import, which is how `@pinia/nuxt` and `unplugin-auto-import` expose it. A file that imports or declares its own `defineStore` is skipped.

Doctor only compares ids that are string literals, or template literals without expressions. Both `defineStore('cart', ...)` and the object form `defineStore({ id: 'cart', ... })` are read. Ids built from variables or expressions are skipped.

Duplicate ids are compared across the files Doctor scans by default, so tests, fixtures, and generated files are excluded. In a monorepo, Doctor compares a store only with stores from the same package, using the nearest `package.json`. This avoids reporting separate apps that each have their own Pinia instance.
