Doctor has separate entry points because each workflow needs different context.

## Run a project check

Use `vite-doctor` when you want one command that runs the scripts already defined by a JavaScript project:

```bash
pnpm dlx vite-doctor
```

Read the [CLI guide](/cli) for package-manager detection, script selection, and automation examples.

## Scan Vue code

Use `vue-doctor` when you want the Vue rule pack directly:

```bash
pnpm dlx vue-doctor
```

Read [Vue installation](/vue/installation) for scan commands, changed-file checks, and CI flags.

## Add Nuxt-aware checks

Install once, get Nuxt-aware checks. The Nuxt module generates Nuxt evidence, can register the `nuxt doctor` command, and exposes the optional MCP endpoint:

```bash
pnpm dlx nuxt module add vite-doctor/nuxt
pnpm exec nuxt doctor
```

Read [Nuxt getting started](/nuxt/getting-started) for the CLI workflow and [Nuxt module](/nuxt/module) for manifest generation.

## Connect agents

Keep the human workflow CLI-first. For agents, use the existing read-only MCP endpoint exposed by the Nuxt module:

```ts
export default defineNuxtConfig({
  modules: ["vite-doctor/nuxt"],
});
```

Read the [Nuxt AI guide](/nuxt/ai) for the MCP tools and client setup.
