---
title: Installation
description: Run Vite Doctor in a Vue 3.5 project.
---

The first npm alpha publishes `vite-doctor` only. Run the smart CLI from a Vue project root:

```bash
pnpm dlx vite-doctor@alpha .
```

Use `scan` or `check` explicitly when you want command names in scripts:

```bash
pnpm dlx vite-doctor@alpha scan .
pnpm dlx vite-doctor@alpha check .
```

## Expected result

The scan prints a text report with file paths, rule ids, messages, and suggestions. It exits with code `1` when it finds blockers or errors, and code `0` otherwise.

## Useful options

| Option             | Use it to                           |
| ------------------ | ----------------------------------- |
| `--changed`        | Scan changed files only.            |
| `--fix`            | Apply safe fixes.                   |
| `--unsafe-fix`     | Apply fixes that may need review.   |
| `--severity error` | Report only errors and blockers.    |
| `--rules <id>`     | Run a specific rule or rule filter. |
| `--max-warnings 0` | Fail when any warning remains.      |

## Project CLI

Use `vite-doctor` when you want Vue diagnostics directly:

```bash
pnpm dlx vite-doctor@alpha . --max-warnings 0
```

The CLI detects Vue projects automatically and applies the Vue rule pack. Read the [CLI guide](/cli) for detection rules, package-manager detection, and automation examples.

## Rule coverage

Vue Doctor focuses on high-signal framework mistakes: prop mutation, missing `.value`, async or impure computed getters, watchers registered after `await`, missing `v-for` keys, unsafe `v-html`, and browser APIs in SSR paths.
