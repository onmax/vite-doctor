The Package Rule Pack analyzes existing files exposed by a package manifest. It is opt-in and works with JavaScript and TypeScript libraries, including framework modules.

Build the library first, then run:

```bash
pnpm vite-doctor . --extends auto,package/recommended
```

For a workspace, run Doctor against each library directory. Run against a staged package directory when publishing transforms the manifest or output.

Doctor follows `exports`, `main`, `module`, `browser`, `bin`, `types`, `typings`, and `typesVersions`, then follows literal imports through local files. Declaration files beside JavaScript entrypoints are included. Source files and unrelated output are not scanned by these rules unless an entrypoint references them.

Doctor does not execute build scripts, import package code, install dependencies, or edit the manifest. A declared dependency range is accepted without checking its installed version. Private packages are skipped. Package analysis uses the manifest and files on disk, so rebuild before relying on its findings. It does not validate tarball inclusion, conditional export precedence, or computed import specifiers. Missing referenced output makes the report incomplete. JSON and agent reports include the missing paths under `evidenceGaps`. Custom loader wrappers and external browser replacements are not analyzed.

You can select the preset in trusted host configuration too:

```ts
import { doctor } from "vite-doctor";

export default {
  plugins: [doctor({ extends: ["auto", "package/recommended"] })],
};
```

Use a standalone Doctor Run after building when the Plugin Surface runs before output has been written.

## Phantom dependencies

`package/no-phantom-dependencies` reports `PKG0001` for an external JavaScript reference and `PKG0002` for an external type reference. Consumer declarations in `dependencies`, `peerDependencies`, or `optionalDependencies` satisfy the rule. `devDependencies` do not. A declared `@types` provider can satisfy a type reference.

Choose dependencies when the library owns the package, and peers when the host must provide it. Doctor suggests that choice without rewriting the manifest or guessing a supported version range. Guarded imports still need a declaration, usually an optional peer.
