The `vite-doctor/h3` Rule Pack checks code written against H3, the HTTP framework under Nitro and Nuxt. It covers request validation, responses, request bodies, HTTP errors, sessions, middleware paths, and the APIs H3 v2 removed or changed. Its diagnostics use the `H3` Diagnostic Code Prefix.

## When it runs

The pack activates per workspace package. A package activates it when it declares `h3` in its dependencies, such as an H3 server on srvx, or when it is a Nitro or Nuxt project, which runs H3 without declaring it. Nitro and Nuxt projects get every H3 rule without extra config.

Most rules target H3 v2, so they read the H3 version each package runs. A package that declares `h3` resolves its own installed copy. A Nitro or Nuxt package uses the H3 that its Nitro owns. The JSON and agent reports list the result for each package under `workspacePackages[].runtimes.h3`, with its `state`, `version`, and `owner`. When a package declares `h3` but Doctor cannot find it installed, the runtime is `unknown`, Doctor reports `DOC0022`, and the version-gated rules stay off for that package.

## What Doctor reads

In Nitro and Nuxt server files, H3 utilities are auto-imported, so a free `readBody` or `createError` counts as H3's.

Everywhere else, Doctor checks a file only when it has a value import from `h3` or `nitro/h3`. Inside that file, a call counts only when it resolves to that import, through a named, aliased, or namespace import. A local function named `getHeader` is not H3's, and a free `createError` in a standalone H3 server is not either. Test files are skipped.

## Install and run

Install Vite Doctor in the project:

```bash
pnpm add -D vite-doctor
```

The Recommended Preset runs automatically:

```bash
pnpm vite-doctor .
```

The Strict Preset adds `h3/middleware/no-exact-path-use`, which reports middleware paths that may be exact on purpose:

```bash
pnpm vite-doctor . --extends auto,h3/strict
```

To diagnose one Rule, select it with `--rules`:

```bash
pnpm vite-doctor . --rules h3/request/prefer-validated-body
```

It reports imports, re-exports, and reads through an `h3` namespace import, and each diagnostic names the replacement from the migration guide when there is one.

## Migrate to H3 v2

Check an H3 1.x server against H3 v2 before changing dependencies:

```bash
pnpm dlx vite-doctor migrate . --to h3@2
```

The report runs the v2 rules as if H3 2.0 were installed and keeps their source changes with the `h3` update in each package that declares it. It then lists checks that must wait until v2 is installed, such as replacing `createServer(toNodeListener(app))`. It does not modify source or package files. `h3@2` applies only to packages that declare `h3` themselves. In Nitro and Nuxt projects, Nitro provides H3, so use `--to nitro@3` or `--to nuxt@5`, which move H3 to v2.
