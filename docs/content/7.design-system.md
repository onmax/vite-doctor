The Design System Rule Pack (`vite-doctor/design-system`) checks that call sites stay inside a Tailwind design system: theme colors instead of raw ones, scale values instead of arbitrary ones, classes instead of inline styles, and component variants instead of restyling. It runs [@shadcn/lint](https://github.com/shadcn-ui/lint) as its engine and reports each finding as a Doctor Diagnostic with a `DS` code. Its Rules inspect JSX in JavaScript and TypeScript files. Vue single-file components are skipped.

The Rules keep @shadcn/lint's ESLint names, so `// eslint-disable-next-line shadcn/no-inline-styles` still silences a finding.

If you are migrating from the Shadcn Rule Pack, regenerate your baseline after updating the Rule IDs. Existing fingerprints for those findings do not match the renamed Rules.

## Install and run

Install Vite Doctor in the project:

```bash
pnpm add -D vite-doctor
```

Doctor activates the Recommended Preset when Project Inventory contains `tailwindcss`. It includes raw colors, arbitrary values, and inline styles:

```bash
pnpm vite-doctor .
```

The Strict Preset includes all six Rules, adding component restyling, unreadable class values, and unknown classes:

```bash
pnpm vite-doctor . --extends auto,design-system/strict
```

To diagnose one Rule:

```bash
pnpm vite-doctor . --extends design-system/strict --rules design-system/no-inline-styles
```

## Component recognition and options

Component-specific Rules need to recognize the project's design-system imports. Pass upstream Rule options through Doctor's rule configuration. For example, this `doctor.config.ts` recognizes components imported below `@/components/ui/` and allows layout classes on those components:

```ts
import { defineDoctorConfig } from "vite-doctor/config";

export default defineDoctorConfig({
  extends: ["auto", "design-system/strict"],
  rules: {
    "design-system/no-restyle": [
      "warn",
      { componentImports: ["^@/components/ui/"], allow: ["layout"] },
    ],
    "design-system/require-static-classes": ["warn", { componentImports: ["^@/components/ui/"] }],
  },
});
```

Load executable configuration explicitly:

```bash
pnpm vite-doctor . --config doctor.config.ts
```

Use the [upstream Rule documentation](https://github.com/shadcn-ui/lint/tree/main/docs/rules) for each Rule's options and recognition limits. The examples demonstrate behavior without a resolvable theme: SVG colors can inherit `currentColor`, and unknown classes are checked against a reduced fallback that includes bundled utilities plus discovered `@utility` names and CSS class selectors. This fallback does not validate theme tokens or provide spelling suggestions. Undeclared color-token checks and theme replacement suggestions require a readable theme. Review suggested edits against the design system before applying them.
