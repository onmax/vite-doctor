title: Getting Started
description: Run the doctor CLI in a Vue or Nuxt project.
---

Doctor ships two CLI entry points backed by the same analyzer:

- `vue-doctor` scans Vue 3.5 projects and libraries.
- `nuxt-doctor` adds Nuxt 4 project detection, Nuxt rules, and optional manifest data.

## Run your first scan

From a Nuxt project root, run:

```bash
pnpm dlx nuxt module add nuxt-doctor
pnpm exec nuxt doctor
```

From a Vue project root, run:

```bash
pnpm dlx vue-doctor
```

The report prints findings grouped by file, rule id, severity, and fix guidance. Doctor exits with code `1` when it finds blockers or errors.

## Use common commands

List the enabled rules:

```bash
pnpm dlx nuxt-doctor rules
```

Scan only changed files:

```bash
pnpm dlx nuxt-doctor . --changed
```

Apply safe fixes:

```bash
pnpm dlx nuxt-doctor . --fix
```

Filter by severity or rule id:

```bash
pnpm dlx nuxt-doctor . --severity error
pnpm dlx nuxt-doctor . --rules nuxt/fetch/no-raw-fetch-in-setup
```

## Config safety

Local `doctor.config.*` files are executable, so Doctor does not load them by default. Use `--config` or `--trusted-config` only when you intentionally trust the repository:

```bash
pnpm dlx nuxt-doctor . --trusted-config
```

## CI

Use `--max-warnings 0` when warnings should fail the job:

```bash
pnpm dlx nuxt-doctor . --max-warnings 0
```
