title: Getting Started
description: Run the doctor CLI in a Vue or Nuxt project.

The first npm alpha publishes `vite-doctor` only. It is the smart CLI entry point backed by the shared analyzer:

- `vite-doctor` scans Vite, Vue, Nuxt, and Nitro projects with auto-detected framework behavior.
- `vite-doctor/nuxt` is the Nuxt module export path from the `vite-doctor` package.

## Run your first scan

From a Nuxt project root, run:

```bash
pnpm dlx vite-doctor@alpha .
```

Install `vite-doctor/nuxt` when you want persistent Nuxt evidence, the optional `nuxt doctor` command, and MCP tools.

The report prints findings grouped by file, rule id, severity, and fix guidance. Doctor exits with code `1` when it finds blockers or errors.

## Use common commands

List the enabled rules:

```bash
pnpm dlx vite-doctor@alpha rules
```

Scan only changed files:

```bash
pnpm dlx vite-doctor@alpha . --changed
```

Apply safe fixes:

```bash
pnpm dlx vite-doctor@alpha . --fix
```

Filter by severity or rule id:

```bash
pnpm dlx vite-doctor@alpha . --severity error
pnpm dlx vite-doctor@alpha . --rules nuxt/fetch/no-raw-fetch-in-setup
```

`vite-doctor` defaults to `--framework auto`. Use `--framework vue|nuxt|vite|nitro` only when auto-detection needs an explicit override.

## Config safety

Local `doctor.config.*` files are executable, so Doctor does not load them by default. Use `--config` or `--trusted-config` only when you intentionally trust the repository:

```bash
pnpm dlx vite-doctor@alpha . --trusted-config
```

## Automation

Use `--max-warnings 0` when warnings should fail an automated check:

```bash
pnpm dlx vite-doctor@alpha . --max-warnings 0
```

Use `vite-doctor` when you want one CLI command that detects the package manager and runs the project's existing check, test, and build scripts. Read the [CLI guide](/cli) for detection rules and automation examples.
