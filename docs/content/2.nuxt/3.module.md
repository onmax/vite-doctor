---
title: Module
description: Generate a Nuxt Doctor manifest from a Nuxt 4 app.
---

The Nuxt module gives the CLI project metadata that static file scanning cannot infer reliably: auto-imports, components, layers, aliases, route rules, server handlers, runtime config shape, and keyed composables.

## Add the module

Add `nuxt-doctor/module` to `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  modules: ["nuxt-doctor/module"],
});
```

Then prepare the app:

```bash
nuxt prepare
```

The module writes the manifest into the Nuxt build directory:

```txt
.nuxt/doctor.manifest.json
```

Nuxt Doctor can scan without the manifest, but the manifest improves auto-import, component, route rule, server handler, runtime config, and layer diagnostics.

## Use the MCP report

The module also exposes read-only MCP tools at `/mcp` by default. Connect an MCP-capable editor or agent to your running Nuxt app and ask for a Nuxt Doctor report.

The built-in tools are:

- `doctor_report` — run a structured read-only scan for the current project.
- `doctor_rules` — list active Nuxt Doctor rule metadata.
- `doctor_explain_rule` — explain a specific rule id.

Disable or customize the endpoint through `doctor.mcp`:

```ts
export default defineNuxtConfig({
  modules: ["nuxt-doctor/module"],
  doctor: {
    mcp: {
      route: "/mcp",
      name: "Nuxt Doctor",
    },
  },
});
```

Set `doctor.mcp` to `false` to disable the MCP endpoint.

Read the [AI guide](/nuxt/ai) for MCP client setup and agent-ready observability with evlog.

## Run through Nuxt

The module also registers a Nuxt CLI command:

```bash
nuxt doctor
```

Use the Nuxt command when you want to scan from automation scripts:

```bash
pnpm exec nuxt doctor
```

## Extend rules from a module

Nuxt modules can add rule packs through the `doctor:extendRules` hook:

```ts
export default defineNuxtModule({
  setup(_options, nuxt) {
    nuxt.hook("doctor:extendRules", (rulePacks) => {
      rulePacks.push(myRulePack);
    });
  },
});
```

Use this for module-specific correctness checks that depend on how your module configures Nuxt.

## Scan module source

Modules can opt into scanning their own runtime source through `doctor:extendSources`:

```ts
import { resolve } from "pathe";

export default defineNuxtModule({
  setup(_options, nuxt) {
    nuxt.hook("doctor:extendSources", (sources) => {
      sources.push({
        module: "my-module",
        root: resolve(import.meta.dirname, "runtime"),
        include: ["**/*.{vue,ts,js,mjs}"],
        exclude: ["**/*.test.*", "**/dist/**"],
      });
    });
  },
});
```

Module rule packs can identify these files with `ctx.file.sourceKind === "module"` or `ctx.file.isModuleSource()`, and can read the owning module from `ctx.file.moduleName`.
