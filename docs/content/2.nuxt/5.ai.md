Nuxt Doctor is designed to be useful from both human workflows and AI-assisted workflows. The CLI gives a local report, while the module exposes read-only MCP tools that agents can call against the running Nuxt app.

## MCP reports

When you add `nuxt-doctor/module`, the module exposes `/mcp` by default. Connect an MCP-capable editor or agent to the running app and ask for a Nuxt Doctor report.

```ts
export default defineNuxtConfig({
  modules: ["nuxt-doctor/module"],
});
```

The built-in MCP tools are read-only:

| Tool                  | Purpose                                                              |
| --------------------- | -------------------------------------------------------------------- |
| `doctor_report`       | Run a structured Nuxt Doctor scan for the current project.           |
| `doctor_rules`        | List active rule metadata, including rule packs added by Nuxt hooks. |
| `doctor_explain_rule` | Return remediation context for one rule id.                          |

The report uses the current Nuxt project root. It does not accept arbitrary filesystem roots and does not expose fix operations.

## Connect a client

Start the Nuxt app, then register the MCP endpoint with your editor or agent:

```bash
npx add-mcp http://localhost:3000/mcp
```

For production docs or internal apps, publish the HTTPS endpoint instead:

```bash
npx add-mcp https://example.com/mcp
```

Customize or disable the endpoint with `doctor.mcp`:

```ts
export default defineNuxtConfig({
  modules: ["nuxt-doctor/module"],
  doctor: {
    mcp: {
      route: "/mcp",
      name: "Nuxt Doctor",
      description: "Read-only Nuxt Doctor reports for this app.",
    },
  },
});
```

Set `doctor.mcp` to `false` to disable the endpoint.

## Agent-ready logs

Nuxt Doctor reports are most useful when agents can combine them with runtime evidence. evlog is a good fit for this workflow because it emits structured wide events, supports `why`, `fix`, and `link` fields on structured errors, and documents an agent workflow around local NDJSON logs.

For Nuxt apps, evlog provides a Nuxt module:

```ts
export default defineNuxtConfig({
  modules: ["nuxt-doctor/module", "evlog/nuxt"],
  evlog: {
    env: {
      service: "my-app",
    },
  },
});
```

Use structured errors when a runtime failure should be explainable to humans and agents:

```ts
throw createError({
  status: 400,
  message: "Invalid payment amount",
  why: "The amount must be a positive number",
  fix: "Pass a positive integer in cents.",
  link: "https://docs.example.com/api/payments#amount",
});
```

If you want agents to inspect logs locally, configure an evlog file-system drain so wide events are written as NDJSON. Then an agent can combine:

- `doctor_report` from MCP for static Nuxt correctness.
- `.evlog/logs/` for runtime errors, slow requests, and request traces.
- `doctor_explain_rule` for rule-specific remediation context.

## AI SDK observability

For apps with AI endpoints, evlog documents an `evlog/ai` integration for the Vercel AI SDK. Wrap models with `createAILogger(log)` to capture model, token, tool-call, streaming, and cost metadata on the same wide event.

```ts
import { streamText } from "ai";
import { createAILogger, createEvlogIntegration } from "evlog/ai";

export default defineEventHandler(async (event) => {
  const log = useLogger(event);
  const ai = createAILogger(log);
  const { messages } = await readBody(event);

  const result = streamText({
    model: ai.wrap("anthropic/claude-sonnet-4.6"),
    messages,
    experimental_telemetry: {
      isEnabled: true,
      integrations: [createEvlogIntegration(ai)],
    },
  });

  return result.toTextStreamResponse();
});
```

`createAILogger` captures model and token metadata. `createEvlogIntegration(ai)` adds deeper telemetry such as per-tool timing and total generation wall time.

## Recommended prompt

After connecting MCP and logs, ask your agent:

```txt
Run doctor_report, explain each blocker or error with doctor_explain_rule, then compare the findings with recent evlog errors in .evlog/logs/. Prioritize fixes that affect production requests.
```
